## Design Specificity Verdict

**LLM 評估：視覺是自己的，構圖和互動是通用的。** 方格紙、墨線框、等寬標註都來自「建築師的方格筆記本」，深淺兩色都成立。但題目卡、右欄進度、題號格、上一題／下一題，換掉 token 和文案後，任何線上題庫都能用。「模擬考」在畫面上只體現為兩件事：交卷前不給判定，以及一個正計時器。真正屬於這個產品的細節是刪去法的刪除線、原題號和一律給分計分。

錯過的機會有三個：題號導覽可以是答案卡；建築考試最有辨識度的圖題沒有自己的版面；交卷沒有收尾的儀式。

**檢測器：** 和這個畫面相關的項目很少，五個優先問題它一個都抓不到，因為全是行為和語意問題。
- **原始碼：** 目標兩檔 0 筆，但 `.tsx` 不會連帶掃它的 CSS module。擴大到 practice 和共用元件後，真的畫在這個畫面上的只有 2 筆 `design-system-font-size`。`.navigator > header h2` 的 15px 屬實（DESIGN.md 是 16px）；側欄 `.navItem` 的 15px 是誤報（DESIGN.md 有記載）。
- **瀏覽器：** 6 個畫面都注入成功。
  - `undersized-ui-text` 每個畫面都有：計分板的「已作答、未作答、難題」只有 9.17px。這是設計評審漏掉、檢測器抓到的真問題。
  - `low-contrast` 有兩種：刪去選項 3.5:1（深色 3.7:1）是 DESIGN.md 指定的值；「返回每日練習」4.0:1 是誤報，取樣剛好落在 1px 方格線上，對紙面實際是 4.96:1。
- **量測：** 320 到 1280 寬都沒有水平溢出，真實頁面沒有 console 錯誤。

**視覺覆蓋層：** 這次是無頭瀏覽器，使用者的瀏覽器裡看不到覆蓋層。

## Overall Impression

讀題和作答單題做得好：安靜、好讀，進度不會丟。問題都在單題以外，也就是「考試」的部分：移動、檢查、交卷。最差的一刻正好是結尾：考完 80 題，交卷只有一個系統對話框，或什麼都沒有；40 格全綠的題號，下一秒變成滿片紅。

最大的機會是把題號導覽做成答案卡，再接上交卷前檢查。這一步同時解決問題 1 和問題 3。

## What's Working

1. **進度不會丟，適合零碎時間。** 重新整理後題號、刪去、時鐘都在；返回不丟資料；第二分頁會即時同步。
2. **閱讀區真的安靜。** 題幹與選項是最大內文，沒有判定色干擾；刪除線加恢復鈕把紙本刪去法搬了進來，刪去後還讀得到。
3. **防呆細節有功力。** 雙擊下一題只前進一題；長題目時底部操作列一直可點；鍵盤進入最後一題時，焦點不會直接落到交卷上。

## Priority Issues

### 1. [P1] 交卷是最高風險的一步，卻最沒有設計

**問題：**
- 全部答完後按交卷，沒有任何確認就直接出分，草稿同時清除（src/features/practice/mock-exam-page.tsx:369-393）。
- 有未作答時是原生 `window.confirm`，只有一句話，不能跳回空白的題目。
- 側欄的實心交卷從 0/80 就在，和「先離開」只隔 8px。最後一題時畫面上有兩顆實心交卷，DESIGN.md 的規則是一個畫面一顆。
- 確認文字會洩露一律給分：只留一題空白時，可能出現「這些題目一律給分，仍會計分」（src/features/practice/mock-exam.ts:292-301）。這句是當初刻意加的（todo/歷史紀錄/todo-歷史紀錄.md:862），但和 PRODUCT.md「作答時不揭示」衝突。

**為什麼重要：** 一份冷卷只能考一次。誤觸交卷後答案已經看過，又沒有復原，這份模擬就作廢了。考前兩週，這個代價特別高。

**修法：** 「隨時可以交卷」可以保留，要改的是「有未作答才確認」這條既定需求（todo/歷史紀錄/todo-歷史紀錄.md:849）：
1. 一律先開「交卷前檢查」浮紙，列出已作答數、未作答題號和標記題號，都能點回該題。以 ConfirmDialog 的 warning 語氣為基礎，它的 description 目前只收字串，要擴充。
2. 按鈕用「回去檢查」和「確定交卷」，預設焦點放在「回去檢查」。
3. 側欄交卷降為次要按鈕，和先離開拉開距離。
4. 拿掉一律給分的文字，結果頁已經會說明。這點要使用者決定。

**指令：** `/impeccable:impeccable shape`，和問題 3 一起做。

### 2. [P1] 手機節奏被打斷，連點還會無聲清掉答案

**問題：**
- 已選 A 時快速點 B 兩下，四列全空，沒有任何提示。手機觸控和桌機雙擊都重測過。第二下被當成「再點一次取消」（src/features/practice/mock-exam-page.tsx:63-70、src/components/ui/ui.tsx:163-168）。
- 「下一題」的高度逐題跳動：390×844 下 Y 座標在 536 到 788 之間，相鄰題最多差 252px。操作列只黏在卡片內，短題時會跟著浮上來。
- 交卷要捲 653px，第 50 題的題號要捲 945px。考古題討論版已有 `QuestionMapDrawer`，這裡沒用（src/features/exams/exams-page.tsx:501）。
- 題號是非 shallow 的 Link，離線時點題號會掉到瀏覽器錯誤頁，下一題則正常。這是 dev 實測，正式環境未驗證。
- 平板：820×1180 仍有 260px 側欄，內容只剩 504px，落入手機版；1180×820 的題號導覽掉到第一屏外。

**為什麼重要：** 單手作答靠肌肉記憶，按鈕每題移動，拇指就要重新瞄準。空白題在作答時不會有警告，通勤搖晃中少掉一題也不會發現。PRODUCT.md 也寫明三種裝置同等重要。

**修法：**
1. 「再點一次取消」是使用者要的功能（todo/歷史紀錄/todo-歷史紀錄.md:1024），要保留，只排除快速連點的第二下（`event.detail > 1`）。間隔開的第二次點擊現在能取消，已確認，修改後要維持。
2. 手機操作列永遠貼視窗底，時鐘和按鈕併成一列，省下約 30px。
3. 加「題號」鈕開 `QuestionMapDrawer`，交卷和先離開一起收進去。
4. 題號改 shallow 導覽。
5. 平板作答時收起站台側欄。

**指令：** `/impeccable:impeccable adapt`

### 3. [P1] 題號導覽用答對綠表示已作答，又幫不上檢查

**問題：**
- 已作答直接用 `--success`（src/components/question-number-button.module.css:33-37）。DESIGN.md 明定綠色只回報答對，這一頁又承諾交卷前不給判定。
- 狀態幾乎只靠顏色：已作答和未作答的底色對比只有 1.15:1（深色 1.21:1）。
- 難題只改 1px 框線，在目前題的深藍底上看不見。
- 想回頭檢查的題目只能記在腦中。難題是全站長期標記，會同步到雲端，不能拿來當「待檢查」。格子也看不到自己選了什麼。

**為什麼重要：** 從每日抽題過來的考生已經學會「綠＝對」，看到滿片綠會以為網站批改過，或得到錯誤的安全感。

**修法：**
1. 新增中性的「已填答」狀態（鉛筆色填底），不動其他頁面的答對綠。格內顯示所選字母，用字形傳達狀態。
2. 難題改用角標。
3. 新增只限本次試卷的「待檢查」和「下一個未作答」。
4. 開啟 `showStatusLegend`，並更新 DESIGN.md 的題號規格。

**指令：** `/impeccable:impeccable shape`

### 4. [P1] 螢幕閱讀器聽不到選項內容，鍵盤作答成本高

**問題：**
- 四個 radio 的名稱全是「第 1 題請選擇答案」，選項文字不在名稱裡。已用 Chrome 的無障礙樹重測（src/components/ui/ui.tsx:172）。OptionGroup 是共用元件，沒有 originalLabel 的作答畫面都有同樣問題。
- 換題沒有朗讀，題目沒有標題。
- 進入最後一題、回到第 1 題時，焦點掉到 `BODY`。
- 沒有鍵盤捷徑，80 題約要 800～1200 鍵。

**為什麼重要：** PRODUCT.md 的無障礙目標寫明鍵盤可操作、螢幕閱讀器可讀。全盲考生聚焦在選項時聽不到內容，核心任務接近不可行。這裡只查了無障礙樹，沒有用 VoiceOver 或 NVDA 實際聽過。

**修法：**
1. `ui.tsx:172` 一律帶上字母和文字的 `aria-labelledby`，這是一行修改。
2. 換題時用 polite live region 朗讀「第 16 題，共 80 題」。
3. 按鈕消失時把焦點移到題目。
4. 加上選答和換題的鍵盤捷徑。方向鍵在 radio 群組裡已用來換選項，不能直接拿來換題。

**指令：** `/impeccable:impeccable harden`

### 5. [P2] 圖題的選項被操作列藏住，圖和選項看不到一起

**問題：**
- 構造 114 年第 49 題在 1280×800 下，第一屏看不到任何選項。操作列看起來就像卡片結尾，沒有「下面還有內容」的線索。
- 1280×620 下可用高度 491px，小於圖加選項的 637px，兩者無法同屏。
- 手機燈箱只把圖從約 306px 放大到 360px，細節還是看不清。

**為什麼重要：** 有圖的題目在結構卷占 38.8%、構造卷占 15.8%，考生要在圖和選項之間反覆捲動。捲動能解決，所以標 P2，但它落在建築考試最核心的內容上。

**修法：**
1. 頁面寬度 900px 以上時，圖題改成圖左題右。
2. 圖片限高（例如 45dvh），細節交給燈箱；手機燈箱要能放大到看清線條。
3. 選項在操作列下方時給明確提示。

**指令：** `/impeccable:impeccable layout`

**Sam（輔助科技）：** 四個 radio 同名；換題無朗讀；題目沒有標題；焦點會掉；圖片 alt 是處理註記。通過的項目：題號格的無障礙標籤有「已作答、已標記難題」，焦點框清楚，200% 縮放還能用。

**Alex（效率型）：** 沒有選答和換題的捷徑；沒有「下一個未作答」；桌機下一題高度也會跳（環控 113 年 535～606）；1920 寬時選項列 1222px，滑鼠從選項移到下一題的行程很長。

**專案 Persona 小涵（首次造訪的跨裝置考生，取自 PRODUCT.md）：**
- 開始作答後時鐘立刻跑，選卷頁沒提過計時。

## Minor Observations

- **計分板標籤 9.17px：** `.scoreboard small` 沒設字級，低於 DESIGN.md 的 11px 下限（src/features/practice/practice-page.module.css:833）。
- **題號導覽標題 15px：** DESIGN.md 是 16px（src/features/practice/practice-page.module.css:886）。
- **內部註記外露：** 題庫 475 筆圖片 alt 有 430 筆是處理註記，燈箱還直接當圖說顯示，例如「第 49 題選項疑似為圖片、PDF 題目區含嵌入圖片附圖」。「疑似」二字傷害「題庫可追溯」的信任感。構造 101 年第 38 題寫「題幹文字疑似未完整擷取」，已查過題目是完整的，錯的是註記。
- **題號導覽被切：** 1280×800 開頁時側欄底部超出視窗 20px，第 41、80 題的目前題號會被切到（src/features/practice/practice-page.module.css:766）。`max-height` 只算了 sticky 之後的位置。
- **手機沒有 radio 圓點：** 沿用 `/daily` 的規則，DESIGN.md 沒有記錄。選取只剩淡底（對紙面 1.19:1）和 2px 左線。
- **刪去文字對比：** 3.5:1（深色 3.7:1）是 DESIGN.md 指定值，停用元件也不受 WCAG 對比要求限制，但考生可能還要重讀。
- **手機多行選項：** 字母和眼睛垂直置中，長選項時字母離第一行很遠。
- **續答位置：** 回到第一個未作答題，不是離開時的題目（離開時在第 6 題，回來在第 4 題）。
- **類別標籤：** 真實試卷沒有，手機又隱藏它。全庫掃描過，不算洩題，但降低擬真度。
- **閱讀字級：** 手機要 4 步才調得到，時鐘在設定開啟時繼續跑。
- **missing 狀態：** 文案要人重新整理卻沒有按鈕，最後一題時完全沒有操作鈕（從程式碼推論）。
- **文案：** 空白 1 題時仍寫「這些題目」。
