# 公告讀取量優化紀錄

## 修改內容

- 公告訂閱仍只讀取 `pushMessages/{messageId}`；顯示、已讀、測試模式、到期與排隊行為不變。
- 新版網站將人次統計寫入獨立文件 `pushMessages/{messageId}/stats/test` 或 `stats/live`，不再因統計變化而更新被所有訪客監聽的公告文件。
- 以原本的瀏覽器回條去重；統計與回條在同一個交易中更新。測試和正式版的回條與統計互相獨立。
- 保留舊版網站對公告文件上統計欄位的寫入相容性，因此舊版開啟中的頁面仍可能暫時造成公告更新；新版讀取量改善會隨使用者更新而生效。

## 如何查看完整人次

舊有數字留在公告文件中，不會刪除或重置。新版數字在公告文件的子集合 `stats` 裡：測試看 `test` 文件，正式看 `live` 文件。文件中的 `delivered` 是顯示人次，`read` 是已讀人次。

總顯示人次 = 舊公告文件的 `delivered`（測試為 `testDelivered`）+ 對應 stats 文件的 `delivered`。總已讀人次也以相同方式將舊欄位 `read`（測試為 `testRead`）加上 stats 文件的 `read`。不存在的欄位或文件按 0 計算。人次依瀏覽器識別，並非精確獨立使用者數。

## 部署順序與檢查

1. 先在 Firebase Firestore 發布本專案完整的 `firestore.rules`；新版統計若規則尚未發布，公告仍可顯示，但人次回條會暫存並等待重試。
2. 再部署新版網站。保留舊規則相容路徑，避免舊頁面在切換期間無法記錄。
3. 使用新測試公告和未使用過的瀏覽器測試：確認公告能顯示、已讀可關閉、stats/test 有相應數字，而且公告原文件不因新版顯示或已讀而更新。
4. 比較相同時間範圍、相近使用人數下 `pushMessages` 與 `stats` 的讀寫，以及整體 Firestore 用量。即時監聽仍有初始讀取，統計交易和安全規則也可能有額外讀取；此修改不保證永遠低於免費額度。

## 驗證

元件與傳輸層測試確認顯示、已讀和新版寫入位置。Firestore 規則應以本機模擬器執行 `npm run test:push-rules` 驗證，包含舊版相容、並行去重、異常寫入及帳號權限；不可將測試指向正式資料庫。
